# AI Business Assistant workbench

The assistant provides five work areas: priorities, collections, quoting, spending and evidence controls. Financial figures follow the shared monthly/year/January-to-date selector; production, stock and supplier checks remain live across all dates. Every analysis shows its local calendar date and shared revision. Older answers are labeled when their period, date or revision differs from the current workspace.

Local analysis is immediate and requires no AI service. It calculates totals using unique invoice identities and the established expense deduplication rule, includes deposits, and rounds after aggregation. It distinguishes invoices with recorded past due dates from missing due dates; cancelled/void invoices are excluded from collection drafts. Undated payroll estimates are disclosed separately. Imported bank coverage is shown as evidence coverage, not a current bank balance. Source gaps remain visible rather than becoming assumed zero values.

Record actions open invoices, quotes, jobs, expense facts, payables, scanned sources or supplier fabric details. Search covers the selected financial records, existing receipt extraction fields and the fabric catalogue. Receipt extraction is labeled as evidence, not an additional expense. Supplier rates include their available price basis, source date, unit and VAT wording; the assistant does not silently choose between supplier bases.

Payment follow-up drafts use a selected invoice's recorded customer, reference, balance and available due date. They add no interest charges or delivery promises and do not send messages. The user can copy or download a draft after confirming receipt allocations.

Choosing Gemini sends a compact structured context through the existing `/api/ai/generate` service and configured Gemini integration. Context includes period/revision, calculated totals, source limits, relevant records and bounded priority lists. It excludes raw document binaries, filesystem libraries, credentials and bank account details. Model results render as plain text. Loading, cancellation, empty replies, non-JSON failures, service errors and timeouts are handled; the local evidence-based answer remains available on failure. The assistant never applies a model recommendation to financial records automatically.

Questions/history otherwise live only in this page session. Saving an answer explicitly adds one working note to the existing shared `aiNotes` collection through the normal save queue; the note records provider, source revision, period, date and summary. Saving the same answer twice is prevented. Saved notes are historical working analysis, not posted transactions or verified accounting conclusions.

Copy/download controls export an answer or a concise business brief. No scheduled tasks, storage locations, authentication settings or deployment configuration are changed. Analysis and interface code are separated into `assistant-core.js`, `assistant.js` and `assistant.css`; the existing page entry point delegates to the module.

Validation covers unique arithmetic, fractional rounding, date boundaries, estimates, incomplete source evidence, bounded retrieval, client-specific collections, supplier rate wording, Gemini failure fallback and note idempotency. Isolated browser checks exercise all 19 screens plus record-backed drafts, date filters, receipt search, Gemini loading and mocked success, plain-text rendering, shared notes and mobile overflow. Provider tests use fixtures; a successful fixture is not a guarantee of live Gemini availability.
